## Reading

- **No trained arm shows a measurable loss.** Across every arm and endpoint the most negative point estimate is −0.012 (Stage 1 PCSTR-d, BFCL live irrelevance). Every procurement-study interval stays above −0.024 (lowest: acknowledgement-reward GRPO, IFEval). The only lower bound past −0.03 is Stage 1 PCSTR-d on BFCL live calls (−0.032, two seeds, point estimate −0.004). The primary non-inferiority test passes for both registered arms on both benchmarks.
- The SFT warm start does not lose either (H1 not supported; point estimates are slightly positive).
- Low abstention on BFCL irrelevance is a **property of the base model** (it calls some function on most items where none fits), not something training introduced (H3 not supported).
- Tool-name randomisation (SR1) does not improve calls on BFCL's unseen schemas either (intervals include 0), consistent with its failure on the renamed ProcureSim API.
- Why so little drift: LoRA r16 adapters, KL β = 0.02, 200 GRPO steps; ProcureSim's tool format is plain text, not the BFCL call syntax, so training does not overwrite it.
- Scope: single-turn function calling and instruction following. Stateful multi-turn retention is R1-T (τ-bench), reported separately. Mitigations (registered conditional, §7) were not needed.
