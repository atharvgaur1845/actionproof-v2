# ActionProof: what the reward can see decides whether a tool agent checks its writes

**Track 3 · AgentTune → AuditKIT · Tiny Aya Global 3.35B**

Real tools sometimes acknowledge writes that never committed. ActionProof is a SQLite customer-support environment in which phantom writes return a byte-identical success acknowledgement, and a deterministic verifier scores every episode from the database state, not the transcript. We ask what GRPO selects when its goal reward reads the tool's acknowledgement instead of the authoritative state. On untouched, pre-registered confirmatory splits (n = 400, two seeds), GRPO with our state-grounded reward PCSTR-d raises verified-success completion from 0.6425 to 0.8425, +20.25 pp [16.4, 24.3] over a tool-trusting reward. A stricter metric that also forbids unrequested writes leaves the state-trained agents unchanged and widens the gap to +41.9 pp.

Three findings carry the work. First, the reward's information source decides whether the agent checks its writes. With two rewards of identical form and one warm start, where only the goal term's source differs, test-IID success is 0.825 against 0.605, and sampled refund read-back after a success acknowledgement moves from 0.25 to 0.71–0.72 under the database reward but falls to 0.10 under the acknowledgement reward. On a later warm start, greedy read-back is 1.00 against 0.00, with two seeds per arm. Second, task composition explains why the acknowledgement reward stops checking. On refund timeouts and unrecoverable refunds, acting on what a read reveals forfeits success acknowledgements, so that reward pays readers less. In a pre-registered test, removing those two task classes restores read-back to 0.669, removing 60 random tasks leaves it at 0.000, and the state reward reads back 1.000 on both pools; the channel × pool interaction is +0.678 [0.605, 0.750], with one seed per cell. Third, execution evidence placed in an LLM judge's prompt is not reliably used. AuditKIT's TaskCompletion judge on Aya Expanse 32B accepts 95% of false completions; given the database's own receipt ledger, it still accepts 72% of the failures that ledger exposes (our prompt: 83% to 46%; Aya 8B: 96–100%), while the deterministic verifier rejects all of them.

We also report limits we found in our own method. GRPO selects a script kept whole from supervised fine-tuning: retries stop at the training depth, and on an unseen write tool the agent reads, sees nothing, and still reports success. In a corrected environment where a timeout can fail before the commit, the state-trained agents read the order and then report the refund done without retrying (0.18 against 0.71 for the tool-trusting agent), because they only ever saw timeouts that commit. Our report-blind state reward also pays an agent for continuing after an unrecoverable refund; a dependency-aware variant fixes the ordering offline, but no policy was trained on it. We do not claim that RL teaches lying, since the warm start already claims false success 87–96% of the time, nor that verification generalises, since transfer to a banking domain fails, nor that the results hold beyond one model family and one environment. The work rests on eleven hash-frozen pre-registrations and a public deviation log. An independent verifier written without our code agrees with ours on all 4,000 confirmatory episodes, and the registered confirmatory test passed (PCSTR-d − outcome = +1.5 pp [0.6, 2.6], p = 0.025). At single-request latency, the state-trained agent completes an episode in 2.5 s median against 10.2 s for the tool-trusting agent.
