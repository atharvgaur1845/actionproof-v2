Scenario model from measured simulator rates; not validated real-world ROI. Rates are measured on ProcureSim's locked txn_test; every dollar figure depends on the assumptions below.

What does a wrong write cost?

A tool can reply ok when nothing was stored, or time out after the write committed. Each agent below was measured on the same 440 locked tasks. Change the assumptions to price its mistakes for your own workflow.

Assumptions

Presets are the three brackets of docs/upgrade/ROI.md §3. The defaults (moderate) reproduce results/impact/impact_txn.json exactly.

Projected cost of each agent's mistakes

Two units, as in write-up §24: per 1,000 workflows that meet an ambiguous-execution fault (the benchmark's mix), and per 1,000 workflows in all (the first, times the fault incidence). Clean workflows are assumed handled correctly by every agent, which favours the acknowledgement-trusting agent. Hover a rate for its count.

Compute and agent time are shown apart from the total: they are small next to the error costs and use separate assumptions (GPU price, seconds per call).

Measured rates and their sources

Counts are pooled over seeds. Model arms run each task once greedily and twice sampled. Scripted policies run each task once. Every count is in the named summary file, which is in the repository and on the Hugging Face traces dataset.

Sensitivity: low, base and high brackets

Each column uses one bracket of ROI.md §3 in full (fault incidence, value, exception cost, late-discovery multiplier, recovery rate). The range over seeds is in brackets.

How the cost is computed

Per 1,000 faulted workflows, for each episode outcome measured on the simulator:

  • False completion (reported done, not done): exception cost x late-discovery multiplier.
  • Duplicate mutation: value x (1 - recovery rate) + exception cost x multiplier.
  • False refund (a committed payment refunded): exception cost x multiplier.
  • Every other episode that is not a verified completion (failed report, escalation, stall): the flagged-exception cost, because a person sees it at once.
  • Optional: an extra loss per partial transaction left unrepaired (default 0; the IMPACT1 model charges it only as an exception).

Per 1,000 workflows in all = the above x fault incidence. Per year = that x volume / 1,000. Seed arms: the mean over seeds, with the range. This is scripts/impact_txn.py's model; the build checks the defaults against its output.

What this page cannot tell you: the real fault incidence of your systems, how an agent behaves outside a simulator, or the cost of building the scripted reconciliation checks (B4), which need the fault taxonomy written down in advance. B4 is a reference, not a trained agent.
