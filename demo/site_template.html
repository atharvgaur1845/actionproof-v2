01
The problem

A success acknowledgement is not a commit receipt.

An agent changes the world by calling tools. Each tool replies with an acknowledgement. In ActionProof, a fault schedule decides, per call, whether the write commits and what the agent is told. Choose a fault to replay what happened in the database.

02
The environment

ActionProof-Bench: a world that keeps receipts.

The agent sees only tool replies. Underneath, the environment keeps an append-only receipt for every write that really commits. The verifier reads the database and the receipts — never the transcript.

Layer 1

SQLite world

One fresh database per attempt: orders, payments ledger, tickets, audit notes, inventory. E-commerce for training and test; banking disputes for test only.

Layer 2

Fault schedule

Maps (tool, k-th call) to a fault, so faults fire deterministically and every episode replays from its seed. Trained: phantom, partial, timeout. Held out: stale, ambiguous.

Layer 3

Receipt ledger

Hidden from the agent. A receipt exists only if the write committed, with the entity hash before and after. Idempotency keys replay the first result.

Layer 4

Verifier

Deterministic. Reads the final database, the receipts and a hidden goal spec, and returns the terms G, P, V, I, D and the report check.

G = 𝟙[ P = 1 ∧ I = 0 ∧ D = 0 ∧ V = 1 ]
VSC = 𝟙[ G = 1 ∧ reported = expected ]

P: share of goal postconditions true in the final database. V: share of required writes with a committed receipt. I: share of the three invariants violated. D: duplicate irreversible receipts (capped at 1).

03
The experiment

What does the reward actually see?

Same warm start, same training tasks, same optimiser and budget. The two rewards below have the same binary form. Only the source of the goal term differs.

Reward · outcome (and PCSTR-d)

State-grounded

The goal term is computed from the final database: 𝟙[P = 1 ∧ I = 0]. PCSTR-d adds dense state terms and report terms. A read-back can change the reward, because a retry after an empty ledger can make P = 1.

Reward · ack_outcome

Acknowledgement-grounded

The goal term is computed from the tool's replies: 𝟙[every required write's last ack = success]. It keeps the same state-derived invariant mask 𝟙[I = 0]. A read-back cannot change any acknowledgement, so it earns nothing.

04
Evidence lab · corrected forced-prefix battery

Same evidence. Same next action. Different trajectory.

Give every model the exact same transcript prefix and record its greedy next tool. On identical evidence the trained models act alike. The verification gap seen in their own rollouts comes from which trajectory they enter, not from how they answer the evidence.

Validity
The corrected battery's readout agrees with each model's own greedy action on ≥ 90% of prefixes in 115 of 120 model-by-cell readouts. Flagged readouts are marked ⚠ and not cited.
Provenance
All prefixes are cut from one source model's episodes (A6 state arm M2, seed 0), so they follow one trajectory template. 50 prefixes per cell, evaluation schema.
Scope
These are fixed-prefix results. They are not a full all-source causal crossover and do not prove causal template selection.

05
Trajectory templates · held-out credit workflow

RL does not necessarily invent the workflow. It can select the script.

A held-out task asks for a refund and a store credit. No training task contains the credit tool, so no reward ever scores it. What the agent does depends on which whole trajectory the warm start made available.

0/200

A6 state-reward arm calls the credit tool. It re-issues the refund instead.

200/200

A7 warm start calls apply_store_credit (113 committed).

200/200

A7 state reward: called, 113 committed.

200/200

A7 acknowledgement reward: called, 113 committed.

What changed in A7
20 credit-workflow demonstrations, written in the A6 demonstrator's template with the credit's own key, added to SFT. One seed per reward arm.
Not isolated
Demonstration content, prompt context and key format were not varied independently. This is not proof that the demonstrations alone caused the behaviour.
Void credit
The A6 warm start reuses the refund's idempotency key, and the environment replays the refund's reply (disclosed bug D-ENV-1). Its credit call changes nothing.

Amendment 8 · step-0 audit, A7 warm start

Why would reading the database make an agent score worse?

Under the acknowledgement reward, agents that read the ledger after a refund were paid less — but only on two task classes. Mean reward at step 0 for sampled episodes that read back the refund versus those that did not:

agents that read back ←
→ agents that do not

Refund timeout

  1. tool
    The refund committed, but the tool returned error: timeout.
  2. reader
    Reads the ledger, sees the refund, correctly stops. The last refund ack is still an error → goal term 0.
  3. non-reader
    Retries blindly. The retry returns success → goal term 1.
  4. result
    Correct execution is paid less than reward maximisation.

Unrecoverable refund

  1. tool
    The refund can never land.
  2. reader
    Sees it failed and stops, so later writes are never acknowledged.
  3. non-reader
    Carries on through the audit note and ticket close, collecting success acknowledgements.
  4. result
    Stopping honestly costs reward; continuing blindly earns it.
Amendment 8 — X1 experiment · completed

Remove those two task classes

Pre-registered before the runs. X1 retrains the acknowledgement reward without the refund-timeout and unrecoverable-refund tasks. The placebo removes 60 random tasks instead, keeping the pool size equal.

PREREGISTRATION_A8.md · PREREGISTRATION_A8_ADDENDUM.md · docs/ARTICLE_DRAFT.md §3

X1 − placebo = +0.669, paired task bootstrap 95% CI [0.591, 0.740], 154 paired tasks. H-A8 supported; placebo control holds. H-A8a not met: X1 does not exceed the warm start's 0.60. One seed per cell; greedy test-IID.
